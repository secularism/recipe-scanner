# Phase 6 CONTEXT — 首页 + 生成页体验升级

## Why This Phase

项目的核心功能已经完整，但用户从首页进入生成页这段体验，还停留在“能用”的层面，没有形成足够强的产品感。现在最值得优化的不是再扩技术边界，而是把“做饭决策入口”做得更顺、更美观、更有场景感。

## Current User Journey

1. 用户打开首页，看到 Hero、主按钮、一键预设、收藏/历史入口。
2. 用户点击主 CTA 或预设进入生成/结果链路。
3. 用户在生成页逐项选择食材、调味料、菜系和口味。
4. 用户点击按钮得到推荐结果。

## Current Pain Points

- 首页虽然已经完成 Phase 5 UI 重构，但主路径和次级入口的视觉权重仍然接近。
- 一键预设更像“技术功能快捷方式”，不够像真正能帮用户做决定的场景入口。
- 生成页虽然支持草稿自动保存，但用户感知不到“系统帮我记住了什么”。
- 已选内容反馈较弱，用户需要来回扫视多个区域，才能确认自己到底选了什么。
- 清空、恢复、编辑、继续生成之间缺少顺手的微流程。

## Desired Outcome

- 首页更像一张“今晚吃什么”的美食产品页封面。
- 用户看到首页时，主 CTA 和场景预设会立刻引导其开始决策，而不是先理解界面。
- 用户进入生成页后，能明显知道自己已经选了什么、还差什么、下一步点哪里。
- 首页到生成页形成完整一致的视觉体验：温暖、精致、生活方式感强，但不失效率。

## Guardrails

- 不做云函数、云开发、登录、云同步。
- 不引入外部菜谱 API 或 AI 生成。
- 不改 matcher/generator 评分规则。
- 不扩展到结果页、详情页、收藏页、历史页的大范围重构。
- 本 phase 先出 UI-SPEC 与实现计划，待 OpenDesign 出图后再进入代码改造。
