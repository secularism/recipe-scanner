# Phase 6 Plan — 首页 + 生成页体验升级

## Objective

在不改动本地匹配逻辑的前提下，升级首页与生成页的视觉呈现和操作效率，让“打开小程序到提交生成”这条链路更像高完成度的美食产品体验。

## Scope

- 首页 Hero、主 CTA、场景预设卡、收藏/历史次级入口重设计
- 生成页信息层级、已选摘要、恢复上次输入、最近使用、清空流程优化
- 对应文案、动效、视觉状态、交互反馈统一升级
- UI-SPEC、实现计划、测试计划与文档同步

## Non-Goals

- 不改 matcher/generator 算法
- 不改结果页、详情页、收藏页、历史页的大范围结构
- 不做登录、云同步、云函数、外部 API
- 不引入 AI 生成菜谱

## Tasks

### 1. 设计契约

- [ ] 产出 `06-UI-SPEC.md`，锁定首页和生成页的视觉方向、模块层级、文案、状态与交互
- [ ] 明确首页预设卡的场景主题与文案模板
- [ ] 明确生成页“已选摘要”“恢复上次输入”“最近使用”的信息结构

### 2. OpenDesign 出图准备

- [ ] 输出给 OpenDesign 的页面清单：首页、生成页
- [ ] 明确 750x1334 设计稿基准
- [ ] 明确“美食产品页”方向的关键词、禁区和对比重点

### 3. 首页实现规划

- [ ] 主 CTA 作为唯一最强入口
- [ ] 预设卡从快捷卡升级为场景卡
- [ ] 收藏/历史入口下沉为次级信息
- [ ] 调整 Hero、标题、副标题与底部辅助文案的节奏

### 4. 生成页实现规划

- [ ] 增加“已选摘要”区域
- [ ] 增加“恢复上次输入”显性入口
- [ ] 增加“最近使用”食材/调味料入口
- [ ] 优化清空、编辑、提交前提示与禁用态反馈

### 5. 实现后验证

- [ ] 回归首页进入生成页的主路径
- [ ] 验证预设卡进入结果页链路不受影响
- [ ] 验证草稿保存、恢复、清空逻辑
- [ ] 验证不影响现有收藏、历史、结果页、详情页逻辑

### 6. 文档同步

- [ ] 更新 `.planning/STATE.md`、`.planning/ROADMAP.md`、`.planning/PROJECT.md`、`.planning/REQUIREMENTS.md`
- [ ] Phase 6 完成后补 SUMMARY/REVIEW

- [ ] `npx tsc --noEmit`
- [ ] `npx tsx tests/e2e.test.ts`
- [ ] `npx tsx tests/matcher.test.ts`
- [ ] `npm run build:mp-weixin`
- [ ] `npm run dev:mp-weixin`

## Acceptance Criteria

- [ ] 首页视觉层级更清晰，主 CTA 与预设卡形成稳定的决策入口
- [ ] 预设卡具有明确生活场景感，而不是普通按钮式捷径
- [ ] 生成页能让用户明显感知自己已选内容和当前状态
- [ ] 恢复上次输入、最近使用、清空等高频动作更顺手
- [ ] 不影响现有本地匹配、历史、收藏和分享能力

## Risks

- 视觉升级可能让组件尺寸变大，影响小屏设备信息承载量
- 最近使用与草稿恢复若界面处理不当，可能造成页面噪音
- 当前分支名与阶段主题不一致，后续提交/PR 时需要用文档说明清楚阶段意图
