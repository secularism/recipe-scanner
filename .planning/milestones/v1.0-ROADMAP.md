# Milestone v1.0: MVP

**Status:** SHIPPED 2026-06-21  
**Phases:** 1-8  
**GSD-tracked plans:** 5  
**Archive note:** Phase directories remain in `.planning/phases/` for traceability.

## Overview

v1.0 shipped the usable recipe generation miniapp and prepared the repository for backend-driven evolution. The user-facing product can generate recipes from local ingredients and seasonings, show details, persist favorites/history locally, and share recipe detail pages to WeChat friends. Later phases improved the visual experience, reorganized the repository into a monorepo, and connected the NestJS backend to PostgreSQL through Prisma.

## Milestone Summary

**Key Decisions:**
- 本地 matcher/generator 继续作为 v1.0 小程序主流程，后端逐步接管接口化能力。
- 仓库采用 monorepo 结构，前端、后端、共享类型和部署资源分目录演进。
- 后端采用 NestJS + Prisma + PostgreSQL，先打通 recipes 只读链路，再扩展写接口。
- phase 执行目录保留原位，ROADMAP 和 REQUIREMENTS 进入 milestone archive。

**Issues Resolved:**
- 小程序端 OpenDesign 重构后的组件渲染、首页插图、预设卡布局和图标问题。
- Nest CLI、lodash、Prisma、build 输出路径和 PM2 云服务启动问题。
- `GET /api/recipes/mapo-tofu` 非 UUID 参数误走 UUID 查询分支导致的 500 问题。

**Issues Deferred:**
- AI 生成菜谱。
- 图片上传识别、OCR 和拍照识别。
- 收藏、历史、识别任务的后端写接口。
- 完整用户资料系统和跨设备同步。

**Technical Debt / Follow-up:**
- 下一 milestone 需要重新定义 fresh requirements。
- 若需要更严格验收证据，应补跑 `$gsd-audit-milestone`。
- 小程序端仍以本地存储为主，后端写接口接入后需要重新设计同步边界。
